# CHANGES.md — Project Simplification Change Log

**Project:** Heart Disease Prediction (Flask + Machine Learning, FYP)
**Date of change:** 17 September 2026
**Purpose of the change:** the original project was too complex to
understand, run and defend at an intermediate level. It was simplified
into a smaller project with the same complete ML workflow, without
rebuilding it from scratch. Every change is listed in this document.

---

## 5. Machine learning changes

### 5.1 Models: 5 + ensemble → 3

| | Old | New |
|---|---|---|
| Models trained | Logistic Regression, SVM, Decision Tree, Random Forest, XGBoost | Logistic Regression, Random Forest, XGBoost |
| Ensemble | Average of 5 models, computed at prediction time, shown with a per-model voting table | Removed |
| What the app uses | Ensemble by default, or a model picked from a dropdown | ONE saved model, selected during training by best ROC AUC |
| Selected model | — | Random Forest (saved in models/random_forest.pkl) |

SVM and Decision Tree were dropped because they added two models to
maintain without changing the conclusion: all models landed within about
one percentage point of each other.

### 5.2 Features: 15 → 13

| Feature | Change |
|---|---|
| age, gender, height, weight, ap_hi, ap_lo, cholesterol, gluc, smoke, alco, active | Unchanged (the 11 form inputs) |
| bmi | Kept — simple and clinically meaningful |
| pulse_pressure | Kept — systolic minus diastolic |
| age_group | REMOVED (binned age bands; hard to justify and duplicates age) |
| high_risk_flag | REMOVED (compound rule: cholesterol ≥ 2 AND systolic ≥ 140) |

Removing the two derived features required RETRAINING, which was done.
The new feature function `compute_derived_features()` lives in
ml_model.py and is imported by train_model.py, so training and
prediction share one implementation and cannot drift apart. The old
design duplicated the formulas in two files and relied on a test to
detect drift.

### 5.3 Preprocessing: 13 steps → 6

| Step | Old pipeline | New pipeline |
|---|---|---|
| Load CSV | Yes | Yes |
| Drop id, age days→years, cholesterol/gluc 0-2 → 1-3 shift | Yes | Yes (unchanged, this fix is important) |
| Remove duplicates | Yes | Yes |
| Physiological filter (impossible values) | Yes | Yes |
| IQR winsorization (outlier clipping) | Yes | REMOVED (kept the pipeline easy to explain; the domain filter already removes impossible readings) |
| Median imputation | Yes | Yes |
| Feature engineering | 4 features | 2 features (BMI, pulse pressure) |
| Correlation pruning step | Yes (no-op on this data) | REMOVED |
| Train/test split | 80/20 stratified, seed 42 | Same |
| StandardScaler fit on train only | Yes | Yes |
| Cross-validation | 5-fold, 5 metrics stored per fold | 5-fold, accuracy + ROC AUC |
| Metrics stored | Accuracy, precision, recall, F1, AUC at TWO thresholds (0.50 and 0.40), Brier score, calibration curve, PR curve, ROC curve data, per-model timings, SHAP image | Accuracy, precision, recall, F1, ROC AUC, confusion matrix, CV AUC — at ONE threshold (0.50) |

### 5.4 Decision threshold: two → one

The old app decided "at risk" at 0.40 (a screening rationale) while
reporting metrics at 0.50, and banded the result into Low / Moderate /
High at 0.40 / 0.70. The new app uses the standard 0.50 threshold
everywhere: LOW RISK below it, HIGH RISK at or above it. The app now
behaves exactly like the reported metrics, which is much simpler to
explain.

### 5.5 Retraining results (real, verified output)

Dataset after cleaning: 68,645 rows (was 64,825 in the old pipeline).
Split: 54,916 train / 13,729 test. Training time: about 56 seconds.

| Model | Accuracy | Precision | Recall | F1 | ROC AUC | CV AUC |
|---|---|---|---|---|---|---|
| Logistic Regression | 72.7% | 0.748 | 0.675 | 0.710 | 0.792 | 0.791 ± 0.004 |
| **Random Forest (selected)** | 73.0% | 0.752 | 0.678 | 0.713 | **0.800** | **0.800 ± 0.004** |
| XGBoost | 73.2% | 0.749 | 0.690 | 0.719 | 0.800 | 0.799 ± 0.004 |

Old project numbers, for comparison: RF 73.4% / AUC 0.798, XGBoost
73.5% / 0.798, ensemble 73.3% / 0.799. The new metrics are slightly
different because the features and preprocessing changed. Everything is
reproducible with `random_state=42`.

## 12. Fixes made during the final review (17 September 2026)

After the simplification, a final review found three problems on the
admin Model Performance page (templates/models.html). All were fixed:

1. **Misleading AUC rounding.** With 3-decimal formatting, Random Forest
   and XGBoost both displayed 0.799 CV AUC and 0.800 test ROC AUC, so the
   "Selected" badge on Random Forest looked wrong (XGBoost even showed
   higher accuracy). The AUC columns now show 4 decimals
   (Random Forest 0.7995 vs XGBoost 0.7986) and the page explains the
   tie-break: when two models tie on test ROC AUC, the better
   cross-validation AUC decides.
2. **Feature-importance bars barely visible.** The bar width was a
   percentage of an auto-sized table cell, so the column collapsed and
   small bars were invisible. The cell now has a fixed width with a grey
   track, and the bar grows inside it.
3. **Logic moved out of the template.** The dense one-line Jinja filter
   that picked the selected model's row was replaced: app.py now computes
   `best_row` with a simple loop and passes it to the template, and the
   comparison table sorts with CV AUC as the tie-break.

Files touched: templates/models.html, app.py (admin_models route only),
static/js/main.js (one small handler that applies the bar widths from a
data attribute - the same pattern the project already used for other
inline styles).

Verified after the fix: the page renders with the correct values
(0.7995 / 0.7986 / 0.8000) and the full test suite passes
(57 passed, 0 failed).

## 13. Ensemble prediction added (17 September 2026, on request)

After the single-model version was reviewed, the ensemble was added back
in its simplest form, on request:

- ml_model.py now loads ALL three saved models. predict() runs each one
  and the final probability is the AVERAGE of the three (the ensemble).
  The individual probabilities are returned as "votes".
- The result page shows a small table - each model and its probability -
  above a note that the final result is their average.
- Saved records store model_used as "Ensemble (3 models)".

Deliberately NOT re-added, to keep the project simple: the model-choice
dropdown, the agreement-percentage box, and per-model thresholds.
Training, evaluation and the Model Performance page are unchanged.

Verified: the full test suite passes (59 checks, including a check that
the ensemble probability equals the average of the three votes) and the
result page renders the three model probabilities.

## 15. PDF report added + screening wording (18 September 2026)

The downloaded report is now available as a PDF alongside the plain-text
version, and it shows BOTH results: the ensemble verdict and each single
model's probability.

- database.py: the predictions table now also stores each single model's
  probability as JSON (votes_json), so the PDF always shows the exact
  numbers the user saw at assessment time. A small migration adds the
  column to existing databases automatically.
- app.py: a new `/report-pdf/<id>` route builds the PDF with a small
  helper written in pure standard-library Python (no new dependency,
  the project still works fully offline). Ownership and admin rules
  are identical to the text report.
- Disclaimer wording strengthened everywhere: app footer, login page,
  assessment form, text report and the PDF now all say
  "Screening tool - not a medical diagnosis".

Verified: 60/60 checks pass, including a check that the PDF downloads
with single + ensemble results.

## 16. How to run the final project

```
pip install -r requirements.txt
python train_model.py        # once
python app.py                # open http://127.0.0.1:5000
python test_project.py       # optional check
```

Sign in with admin / admin123 (created automatically on first run), or
create a Patient account on the Register page.
